## 🪩 Правила добавления кода в проект

1. Выбрать себе задачку из `To do` и перенести ее в `In progress`.

2. Создать отдельную ветку для задачки с названием:
`label` / `номер issue`.

    - Например: `backend/13` или `ml/10`.
   
3. Добавляем понятные названия коммитиков чтобы легко разбираться.

4. После того как все сделали, пушим и создаем `PR` с названием `PR: название` и описанием по шаблону.

    - Например: `PR: Fix Add Endpoint`.
   
5. Добавляем `Reviewers` и переносим задачу в `In review`.

6. Если все ок, то мерджим с названием `Merge pull request: название ветки`.

    - Например: `Merge pull request: backend/13`.

7. Удаляем отдельную ветку.

8. Отмечаем задачку как выполненную (`Done`).

9. Переходим на ветку `main` и **подтягиваем** все новые изменения! (команды для этого ниже в файле).

10. Делаем все по новой с пункта 1.

## 🤩 Git команды

> Везде заменить `BRANCH` на название нужной ветки!

- `git status` - статус репозитория
- `git add .` - добавить ВСЕ изменения
- `git commit -m "COMMIT MESSAGE"` - закоммитить изменения
- `git push -u origin BRANCH` - запушить изменения
- `git checkout BRANCH` - переместиться на другую ветку
- `git checkout -b BRANCH` - создать новую ветку и переместиться на нее
- `git pull origin BRANCH ` - подтянуть удаленные изменения

#### Добавить себе в ветку изменения из `main`:

```bash
git checkout BRANCH # переключаемся на нашу ветку

git fetch origin # получаем последние изменения из удаленного репозитория

git merge origin/main -m "MERGE MESSAGE" # мерджим изменения из main в нашу ветку
```

#### Рещение конфликтов при `merge`:
1. Открываем файлы с конфликтами и разрешаем их
2. Добавляем исправленные файлы `git add FILE-NAME`
3. Продолжаем процесс `git merge --continue`

#### Шаги перед PR

```bash

```
